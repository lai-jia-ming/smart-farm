总架构原理

三层一闭环 · 具身工场技术架构

从对话交互到底层硬件执行，贯穿全栈的 Self-Healing 自愈闭环。

L1 · 对话交互层

Conversational Layer

用户在工场终端中以自然语言描述功能需求，如"点亮三盏 LED 流水灯"或"读取温湿度传感器数据"。系统内置动态打字机效果实时回显，支持中英文混合指令解析。

自然语言意图识别上下文感知
L2 · AI 处理层

AI Processing Layer

AI Agent 接收自然语言指令，基于知识库匹配硬件模板，自动生成规范化的 C / C++ 源代码。内置代码审查机制，确保寄存器配置、引脚映射、时钟树初始化的正确性。

AI Agent代码生成静态分析模板引擎
L3 · 编译部署层

Build & Deployment Layer

运行于 Linux 宿主环境（香橙派）之上，调用 ARM-GCC 工具链自动编译源码，生成 Hex/Bin 二进制固件，并通过 ST-Link 调试器自动烧录至目标硬件。全过程无需人工干预，秒级完成。

ARM-GCCST-LinkOrange PiMakefile
L4 · 硬件执行层

Hardware Execution Layer

STM32 底层硬件接收固件并执行：GPIO 控制、PWM 输出、ADC 采样、I²C/SPI/UART 通信……物理世界与数字代码在此交汇，实现真正的"具身智能"。

STM32GPIO/PWMI²C/SPIFreeRTOS

Self-Healing 自愈闭环

当编译出错或硬件运行异常时，串口日志实时回传至 AI Agent。 Agent 自动诊断错误根源，修正代码并触发重新编译-烧录循环， 直至硬件按预期运行。全程无需人工介入，实现开发闭环自治。

● 编译 ● 烧录 ● 验证

AI Agent vs 传统物联网方案

直观对比具身工场 AI Agent 方案与传统开发模式在各维度的巨大优势。

对比维度 具身工场 · AI Agent 方案 传统物联网方案
逻辑开发 聊天即定义：自然语言（中英文混合）描述功能需求，AI Agent 自动生成完整工程代码 手写 C/C++ 代码、翻阅数千页 Reference Manual 配置寄存器、手动编写 Makefile
迭代周期 秒级闭环：修改描述 → AI 重生成 → 自动编译烧录 → 验证，平均 <30 秒 手动改代码 → 编译（分钟级）→ 手动烧录 → 验证，单次迭代 5~15 分钟
智能水平 自适应进化：AI 可根据上下文理解意图、自动匹配硬件模板、优化代码结构 固定规则逻辑，无法自动适配硬件变化或优化代码，完全依赖开发者经验
学习门槛 零基础友好：无需掌握 ARM 架构、寄存器映射、时钟树配置，用自然语言即可开发硬件 需要掌握嵌入式系统、C 语言、电路基础、RTOS、调试工具等多领域知识
调试排错 自动化自愈：编译错误或运行异常时，AI Agent 自动诊断并修复代码，重新编译烧录 人工分析串口日志、定位 Bug、修改代码、重新编译，循环往复直到修复
教学效率 10 倍速教学：学生聚焦系统设计与创新思维，而非繁琐的配置与调试细节 70% 时间花费在环境搭建、工具链配置、寄存器查阅等非核心学习内容上
具身工场 不是要替代嵌入式工程师，而是让开发者的精力回归 系统设计与创新 本身
